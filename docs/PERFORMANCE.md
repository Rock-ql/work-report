# 月度绩效考核

## 网页使用

工作报告系统侧栏 → **月度绩效**（`/performance?month=2026-08`）。默认选择上月，可切换历史月份。

1. 通过月份输入、前后月箭头或历史考核选择月份；“回到上月”可快速回到默认月份。
2. 默认使用**系统日报**：仅汇总该月日报的 `sections.todayCompleted`，不读取明日计划、待办或协助事项作为成果。
3. 日报不完整时，选择**线下工作清单**，导入 UTF-8 `.md` / `.txt` 文件（最大 500 KB）或粘贴正文。
4. 点击**生成七项初稿**。此步骤只生成草稿，不写磁盘，也不修改日报。生成成功后自动收起设置；已有考核可通过**生成设置**展开，重新生成前会要求确认。
5. 展开“提交前核对”提示与依据原文，使用与日报同源的 Markdown 编辑器逐项修改。支持**编辑 / 分栏 / 预览**三种模式、格式工具和撤销；窄屏分栏上下排列。
6. 点击固定顶栏的**保存考核**，或按 **⌘S / Ctrl+S**。绩效初稿需要人工核对，因此不自动写入正式考核。
7. 每项标题右侧的复制按钮仅复制对应完成情况；顶栏**复制全部**与**更多操作 → 下载文本**输出标题和七项完成情况。**更多操作 → 读取已保存版本**可恢复磁盘版本；存在未保存修改时需确认放弃草稿。

保存后的考核保存在 `data/performance/YYYY-MM.json`（沙箱遵循 `WR_DATA_DIR`）。覆盖前自动快照，采用乐观锁拒绝其他页面/AI更新后的盲覆盖。冲突时保留编辑区内容，可先复制草稿，再读取磁盘版本核对。

未保存的考核草稿保存在当前标签页的 `sessionStorage`，按数据目录和月份隔离；切换月份或刷新可恢复。浏览器禁用存储或清理标签页后不保证恢复，请及时保存。导入或粘贴但尚未生成的清单，也会按数据目录和月份保留在当前标签页；读取已保存版本成功后才清理本地草稿。

## 七项模板

- 项目交付及时率（25%）
- 代码交付质量合格率（20%）
- 线上问题修复闭环率（20%）
- 产品性能达标率（15%）
- 专利类（加分）
- 技术经验分享（加分）
- 项目流程规范类（减分）

沿用用户给定权重（常规项合计 80%），不擅自补齐其他项目，不计算总分。

## 生成口径

网页未配置外部模型，使用**本地关键词/状态规则整理初稿**，不是 AI 语义推理，不宣称全自动准确归类。来源原文和日报日期随考核保存，支持核对；AI Agent 也可阅读这些来源，归纳更自然的七段完成情况，通过下述 CLI 保存。

- 合并完全重复条目，不把重复日报条数当需求交付数量。
- 未完成、开发中、联调中、计划状态优先于勾选标记；不推导已上线或已闭环。
- 无完整计划/实际交付日期，不推导 100% 按时或 ≥95% 达标。
- 无缺陷台账，不声称 P0/P1 为零；无问题分母和验证记录，不推导闭环率。
- 无性能测量和验收，不声称性能达标或无停机。
- 正文是面向领导的成果总结，不包含“规则摘录”“缺少台账”“待核实”“不能判定”等内部审核用语；这些说明只进入 `warnings`，不进入复制和下载文本。
- 无专利/分享记录时，默认表述为“本月不申报……加分”，不宣称没有产出。其他维度完全没有成果依据时留空，内部提示补充，不编造达标数字。方案宣讲不自动等同于技术文章。
- 日报覆盖只代表系统记录天数，不能作为出勤率；节假日/调休未配置，不声称完整覆盖应工作日。
- 导入清单的月份须人工核对；冲突或跨月待办须人工确认。

## AI / CLI

月度绩效是独立业务数据，不改变日报/周报的类型联合与人工字段保护。生成绩效**不抓 git 提交**，因为依据是已经存在的日报或用户提供的离线文本。

```bash
# 从系统日报导出规则初稿补丁（不会写入考核）
node scripts/report.mjs generate --type performance --month 2026-09 > /tmp/performance-patch.json

# 或从离线清单导出补丁
node scripts/report.mjs generate --type performance --month 2026-08 --source /path/to/8月工作清单.md > /tmp/performance-patch.json

# AI核对原文后可编辑补丁中的七项sections，不要伪造source；写入统一保护通道
node scripts/report.mjs write --type performance --month 2026-08 --patch /tmp/performance-patch.json

# 默认拒绝覆盖已有考核。确需重写，核对现有人工内容后显式加 --replace
node scripts/report.mjs show --type performance --month 2026-08
node scripts/report.mjs validate
```

补丁仅允许 `sections`、`source`、`warnings`。`createdAt`、`updatedAt`、`schemaVersion` 由服务维护。既有日报和周报必须继续遵循 `docs/AI_SPEC.md` 四步流程；本功能不放宽其人工字段约束。

## 验证

一切测试都必须设置 `WR_DATA_DIR` 或使用沙箱；不在真实数据上跑浏览器自动化。

```bash
pnpm sandbox:seed
pnpm dev:sandbox
node --test scripts/performance.test.mjs
WR_DATA_DIR=.sandbox/data node scripts/report.mjs validate
pnpm typecheck
pnpm build
```

应用依赖 Vite 的本地数据中间件，纯静态部署不具备读写 API。开发服务会监听代码；若使用 `pnpm preview`，先重新构建并重启预览服务，再刷新页面。
